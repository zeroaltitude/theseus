# Hook systems compared: Claude Agent SDK, "Bedrock" (Strands SDK, AgentCore Gateway, Bedrock Agents), OpenClaw

_Tabitha, 2026-09-24. Sources: code.claude.com hooks reference and SDK hooks page; strandsagents.com hook-events reference and `strands.hooks.events` API (harness-sdk repo); AWS AgentCore Gateway interceptor types page; Bedrock Agents Lambda parser page; OpenClaw `docs/plugins/hooks/*` in the integration checkout._

"Bedrock hooks" is three different things, and they sit at three different layers:

1. **Strands Agents SDK** (AWS's open-source agent framework, Python and TypeScript): in-process, typed event objects with mutable fields. This is the direct peer of the Claude Agent SDK's callback hooks.
2. **AgentCore Gateway interceptors**: Lambda functions on the *network* boundary between an agent and its tools (MCP or HTTP targets). REQUEST and RESPONSE only.
3. **Bedrock Agents parser Lambdas**: override the *output parser* of the managed agent's prompt templates (pre-processing, orchestration, routing classifier, post-processing, knowledge-base response, memory summarization). Not hooks on events; a replacement for a fixed pipeline stage.

## 2. What each one is good at

**Claude Agent SDK / Claude Code.** Breadth and operator ergonomics. The event taxonomy is the most complete (tasks, compaction, model switch, elicitation, worktrees, config changes), the JSON contract is well documented per event, `defer` is a clean primitive for host-owned approval UIs, and hooks can be a model (`prompt`, `agent`). Its weaknesses are the exit-code footgun, fail-open timeouts on command hooks, best-effort `if` filtering, and discovery from the working tree.

**Strands.** The cleanest *programming model* of the three: one dataclass per event, mutate the field you mean (`cancel`, `retry`, `end_turn`, `resume`, `selected_tool`), reverse ordering for teardown events, and `HookProvider` as the bundling unit so a "plugin" is literally a set of callbacks. Two ideas Theseus should notice: `AfterInvocationEvent.resume` (a hook can re-invoke the agent with new input, which is how Strands does autonomous looping) and `BeforeModelCallEvent.projected_input_tokens` (the budgeter's input, exposed to hooks before the call). Weaknesses: no filtering, no timeouts, no distinction between gating and observing, and in-place mutation means later callbacks silently overwrite earlier ones.

**AgentCore Gateway interceptors.** Not an agent hook system at all; a network policy point. Its virtue is exactly that: it sits where credentials, budgets, and PII masking belong, outside the agent's process, and it works for any agent framework because it speaks MCP and HTTP. It cannot see the model, the prompt, the transcript, or the reason a tool was called. It is the right shape for "tighten at the boundary," the wrong shape for "understand the turn."

**Bedrock Agents parser Lambdas.** A different design lineage: a fixed pipeline of prompt stages with replaceable parsers. `PRE_PROCESSING` returning `isValidInput` is the ancestor of the input classifier idea, and `ASK_USER` as an invocation type is the ancestor of `defer`. Rigid, tied to the managed agent's templates, and largely superseded by AgentCore.

**OpenClaw.** The most *operationally* mature: an explicit per-hook table of default timeout and failure policy, fail-closed gates named as such, operator-tunable budgets in config without patching plugin code, registration gates for conversation access and prompt injection, merge contracts written down per hook (first-defined override, intersected tool restrictions, last content wins), and hook kinds (Modify, Claim, Gate, Observe, Sync, Evaluate) with different execution contracts. Its weaknesses, which we know first hand: the taxonomy grew by accretion (45 hooks, several overlapping), the CLI-runtime path bypasses the embedded-runner hooks (the `before_model_resolve` gap we hit with the Jev router), observe hooks are explicitly not a durable event queue, and hook runs are not ledger records.

## 3. What Theseus takes from each

| From | Take | Why |
|---|---|---|
| Claude SDK | Event taxonomy by cadence; `defer`; deny > defer > ask > allow; `additionalContext` caps; stop-override cap; model-as-handler (our Jev pack handler) | Best-documented contract; `defer` is our confirm gate |
| Strands | One typed event object per hook with explicit mutable fields; `HookProvider`-style bundling (a plugin registers a set); reverse ordering for `After*` events; `projected_input_tokens` exposed pre-call; `resume` as a first-class "re-invoke with input" | Cleanest programming model for compiled-in and WASM plugins; `resume` maps onto our harness-loop wake |
| AgentCore | Keep boundary policy at the boundary: credential injection, budget capping, and PII masking happen in the policy gate and the external-action layer, not in agent-loop hooks | Hooks tighten within policy; they are not the security boundary |
| Bedrock Agents | `isValidInput`-style pre-classification as a deterministic stage before any model call | This is our `CLASSIFY` step, with Jev as the classifier |
| OpenClaw | Per-hook failure-policy table (fail-closed gates named); operator-tunable timeouts; registration gates for conversation access; written merge contracts per hook; hook kinds with distinct execution contracts | We learned these the hard way; they are the operational half the SDKs lack |

## 4. What Theseus does that none of them do

- Every hook invocation is a **ledger row** (event, handler id and version, input hash, result, latency). None of the four record hook runs as first-class data.
- Hooks on **memory ingest and recall**, on the **assembled context manifest**, and observe-only on **judgments**. The SDKs hook the model call and the tool call; none hooks the context selection or the memory decision.
- Hooks **never widen authority**; a hook `allow` cannot override a policy deny. Claude Code's `PermissionRequest` hook can grant permission on the user's behalf; Strands `BeforeToolCallEvent` can swap in any tool; OpenClaw `before_tool_call` can rewrite params. Theseus permits tightening and transforming inputs only within what policy already allows.
- **Fail-closed by kind, fail-open by kind**, decided per hook kind (gating vs observer) rather than per event name, so a new event inherits the right policy automatically.
- A **recursion exclusion** that is structural: hooks fire no hooks, judgments are not hookable for veto, heartbeat and judgment nodes are excluded from the memory pass.
